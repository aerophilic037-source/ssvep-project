1. 자극 없이 30초 — 수집 시간축

Ganglion의 BLE 패킷 하나는 두 EXG 샘플을 담을 수 있어, GUI 원본에서 같은 timestamp·Sample Index가 두 번 나오는 것은 그 자체로 손실이 아닙니다. 이번 도구는 이를 구별합니다. 반대로 LSL의 역전 시각은 분류를 보류하고 수신 순서대로 원본을 보존합니다. 누락을 메우거나 행을 정렬해 정상처럼 만들지 않습니다. Ganglion 데이터 형식.

2. 정지 → 눈 깜빡임 → 정지 → 턱 → 정지

앱의 ‘② 눈·턱 아티팩트’는 각 15초를 기록합니다. 눈 깜빡임은 약 3초 간격, 턱은 통증 없이 짧게 힘주기 3회입니다. 이 단계는 센서가 신체 전위와 움직임에 반응하는지, 오염이 어떤 모습인지 배우는 양성 대조입니다. 눈·근육 신호가 보인다고 EEG가 확인된 것은 아닙니다. 후두부만 있으면 눈 신호가 약할 수 있습니다. 필요하면 별도 세션에서 한 전극을 Fp1/Fp2로 옮겨 비교한 뒤 후두부에 되돌립니다.

원시 파형에서 평탄·계단·튀는 구간·입력 범위 근처 값과 PSD의 좁은 선을 봅니다. 턱의 넓은 고주파 증가는 감마 뇌파의 증거가 아닙니다. 필터를 켜면 보기 좋아질 수 있으므로, 원본과 1–40 Hz 표시를 함께 보세요.

공통 잡음이 크면 REF 접촉 → D_G 접촉 → 입력 스위치 → 케이블 고정 → 전극 접촉 → 주변 전원·조명 순으로 한 변수씩 바꿔 30초를 다시 기록합니다. 노트북 충전기 유무, 책상/전선과 거리, USB 연장선으로 동글 위치를 바꾸는 비교도 가능합니다. OpenBCI 잡음 줄이기.

전극·케이블 문제와 보드 입력 문제를 나누는 교차 검사

먼저 수집을 멈춥니다. 불량 위치의 전극·케이블 묶음 A와 양호한 묶음 B를 표시하고, 두 묶음이 꽂힌 보드의 + 입력만 교환합니다. 공통 REF/D_G와 해당 입력의 DOWN 상태는 유지합니다. 30초 재녹화에서 문제가 A를 따라가면 전극·접촉·케이블 쪽, 같은 보드 채널에 남으면 입력·핀·설정 쪽을 우선 조사합니다. 한 번만으로 결함을 확정하지 말고 원래 연결로 되돌려 반복합니다. 분리 가능한 케이블이면 다음 실험에서 케이블만 바꿔 더 좁힙니다.

전극을 뽑아 입력을 공중에 띄운 상태는 ‘잡음이 없어야 하는 대조’가 아닙니다. 부유 입력은 주변 전자기장을 크게 받을 수 있습니다. 보드 자체 잡음 검사는 사람이 완전히 분리된 벤치에서, 정확한 하드웨어 버전에 맞는 종단/단락 fixture로 숙련자와 진행합니다.

3. 눈 뜸/감음 — 알파 반응 3쌍

음성 시험이 들리는지 확인하고 ‘③ 알파’를 시작합니다. 20초 눈 뜸과 20초 눈 감음을 3쌍 기록하며, 두 번째 쌍은 순서를 뒤집습니다. 전환 준비 5초와 구간 시작 2초를 분석에서 제외합니다. 눈을 감을 때 얼굴에 힘을 주지 않습니다. 비교하는 신호는 주로 8–13 Hz 알파입니다.

보고서는 채널별 감음/뜸 알파 파워 비를 10 log10(Pclosed / Popen) dB로 보여 줍니다. +3 dB는 파워 약 2배입니다. 작업용 반복성 기준은 최소 3쌍 중 2/3 이상에서 +3 dB입니다. 상대 파워, 전체 PSD 모양, 원시 움직임도 함께 봅니다. 이 기준은 임상 정상 판정이나 검증된 Ganglion 합격 규격이 아닙니다.

반복되는 후두부 알파 증가는 유용한 생리적 근거입니다. 반응이 약하면 전극 접촉·REF·개인 알파 주파수·졸음·자세·주변 광원을 재점검합니다. 반응이 약한 사람도 있으므로 ‘알파 없음 = 뇌파 없음’으로 결론내리지 않습니다. LSL만 실패한다면 앞의 GUI-only 파일 비교를 사용합니다.

귀 REF 접촉을 충분히 개선해도 품질이 좋지 않다면, 별도 세션에서 Cz REF를 비교할 수 있습니다. 아래 Ganglion 연구에서도 REF 배치를 바꾸어 사용했습니다. 다만 EEG는 기준 전극과의 전위 차이므로 montage를 바꾸면 측정 신호도 바뀝니다. 진폭이 커졌다는 이유만으로 더 좋은 배치라고 결론내리지 말고, 각 배치 안에서 잡음·접촉·EO/EC 반복성을 비교합니다.

4. 화면 — EEG와 독립적으로 검사

이 컴퓨터를 준비하면서 조회한 OS 정보는 Apple M3, 내장 Color LCD, 60.00 Hz였습니다. 아침에 다른 디스플레이나 설정을 쓰면 실제 값으로 바꾸세요. 이 OS 표시는 광출력 측정을 대신하지 않습니다.

가능하면 디스플레이를 고정 60 Hz 또는 고정 120 Hz로 설정하고, 가변 주사율·절전·화면 자동 밝기·동영상·다른 무거운 작업을 줄입니다. 앱의 10초 타이밍 검사는 깜빡임 없이 rAF 간격을 기록합니다. 작업 기준은 50 fps 이상, 추정 누락 1% 이하, 100 ms 이상의 큰 공백 없음입니다. 평균 FPS만으로 통과시키지 않습니다.

60 Hz에서는 10/12/15 Hz 주기가 각각 6/5/4 프레임입니다. 12 Hz를 50% 흑백 사각파로 만들 때는 반주기 2.5프레임 문제가 있으므로 이번 앱은 시간 기반 사인 밝기를 씁니다. 모든 주사율에서 물리적 광파형이 같다는 뜻은 아닙니다. CSS 밝기와 실제 휘도는 감마·패널 응답·PWM의 영향을 받습니다.

실제 화면 검증은 포토다이오드와 독립된 계측기로 빈도·주기 누락을 측정하는 것이 좋습니다. 고속 카메라는 거친 확인에 유용하지만 rolling shutter와 촬영 주파수 alias가 있어 정밀 동기화의 대체재는 아닙니다. 이 앱은 HTTP 시작/종료와 상대 프레임 시각을 저장하며, 실제 광출력 onset이나 EEG 위상 동기를 보장하지 않습니다. PsychoPy 타이밍 문서.

5. 먼저 15 Hz 한 개 — 정지 화면과 3쌍 비교

‘⑤ 먼저 15 Hz 하나’를 선택합니다. 정지 사각형 10초 → 같은 위치의 15 Hz 자극 10초를 3쌍 기록하고 구간마다 준비/휴식 5초를 둡니다. 15 Hz를 먼저 보는 이유는 흔한 10 Hz 자발 알파와의 혼동을 줄이기 위한 실험 선택입니다. 누구에게나 가장 잘 맞는 주파수라는 뜻은 아닙니다.

15 Hz 및 30 Hz에서 주변 빈 대비 SNR과 정지 화면 대비 변화를 봅니다. ‘피크 하나 있음’보다 자극을 켰을 때만 커지고, 껐을 때 줄고, 다른 주파수를 주면 피크도 따라 이동하는지가 핵심입니다. 기본파 또는 고조파 하나가 약할 수 있으므로 모든 성분이 동시에 보여야 한다고 요구하지 않습니다.

확인되면 10/12/15 Hz 각각의 대조 실험을 진행합니다. 각 회차의 주파수 순서는 고정 seed로 섞고, 같은 주파수의 OFF/ON을 비교합니다. 디스플레이를 보지 않는 대조도 추가하면 자극과 무관한 전기적 유입을 의심하는 데 도움이 됩니다. SNR은 MNE의 인접 주파수 비교 방식에 기반하되, 본 도구의 값은 4초 Welch 창·0.25 Hz 해상도 기준입니다. MNE SSVEP 분석 예제.

6. 3지선다 — 정답률, 보류, 시선 이탈 오탐

단일 자극 반응을 확인한 뒤 ‘⑥ 3지선다’를 실행합니다. 10/12/15 Hz 각 5회, 총 15회와 시선 이탈 대조 5회를 사용합니다. 한 회차는 6초입니다. 시선 이탈 대조에서는 세 자극이 켜진 상태로 화면 밖의 정지 물체를 눈을 뜨고 봅니다. 휴식 대조에서 자꾸 10 Hz로 선택되면 알파·공통 잡음·불충분한 보류 기준을 의심합니다.

보고서는 전체 시도 정확도, 채택된 시도의 정확도, 채택률, 혼동행렬, 시선 이탈 오탐을 따로 제공합니다. 품질 실패와 보류를 빼서 정확도를 부풀리지 않습니다. 1/3 우연 수준의 이항 p값은 소표본 탐색용입니다. 이 결과만으로 실제 사용 성능을 확정하지 마세요.

현재 CCA 점수 ≥0.35, 1·2위 차이 ≥0.08은 기존 앱과 같은 초기 기준입니다. 조정하려면 별도 보정 세션에서 고르고 새로운 평가 세션에서 확인합니다. 같은 trial을 겹치는 창으로 잘라 학습/평가에 나눠 넣거나, 정답률이 가장 좋은 채널·필터를 고른 뒤 같은 데이터로 최종 정확도를 보고하지 않습니다.

GUI 우회 수집 — 약 83 Hz 문제를 분리하는 선택 실험

별도 환경 .venv-brainflow-validation에 BrainFlow 5.24.0과 필요한 의존성을 준비했습니다. 기존 GUI의 라이브러리는 바꾸지 않았습니다. GUI를 완전히 종료하고 실행하세요. 보드에 동시에 두 프로그램이 연결하면 비교가 성립하지 않습니다. 보드 firmware나 sample-rate 명령은 이 스크립트가 바꾸지 않습니다.

# 현재 연결된 동글의 포트 확인 (이름은 재연결 때 달라질 수 있음)
ls /dev/cu.usbmodem*

# 아래 포트 문자열을 방금 확인한 실제 경로로 바꿔서 실행
.venv-brainflow-validation/bin/python software/ganglion/capture_brainflow.py \
  --transport dongle --serial-port /dev/cu.usbmodem11 --seconds 30

보드가 여러 개라면 GUI 로그에 나온 해당 보드 주소를 --mac '보드주소'로 명시합니다. 5.24.0의 네이티브 BLE 경로를 별도로 비교할 때는 --transport native --firmware 3를 사용합니다. 기존 로그에서 firmware 3을 확인했지만 다른 보드라면 실제 버전을 확인하세요. 네이티브 경로는 macOS Bluetooth 권한이 필요할 수 있습니다. GUI의 BLED112 경로와는 다른 실험 조건으로 기록합니다. BrainFlow 공식 안내.

로그·원시 보드 행·4채널 NPZ·HTML 보고서가 software/ganglion/validation_reports/direct/에 저장됩니다. Ctrl+C로 중단해도 가능한 부분 기록을 저장합니다. 직접 경로에서도 낮은 수신률이면 하드웨어·무선·드라이버 쪽 조사가 우선입니다. 직접 경로만 정상이면 GUI 버전/내장 BrainFlow/수집 설정 차이를 의심할 근거가 됩니다. 어느 경우에도 한 번의 비교로 firmware 결함을 확정하지 않습니다.

다른 컴퓨터에서 선택 환경을 다시 설치할 때
python3 -m venv .venv-brainflow-validation
.venv-brainflow-validation/bin/python -m pip install \
  -r software/ganglion/requirements-brainflow.txt

장치가 없는 소프트웨어 검사: --transport synthetic --seconds 5. 이 모드는 BrainFlow 합성 보드(250 Hz)를 사용하며 실제 Ganglion 검사와 구분합니다.

일반적인 랩에서 새 EEG 장비를 확인하는 순서

모든 랩에 동일한 한 가지 SOP가 있는 것은 아닙니다. 여기서는 계측 검증과 연구 재현성 원칙을 이 장비에 맞게 적용했습니다. 환경·참가자 지시·전극 montage·저장·아티팩트 확인·스펙트럼·통계 해석을 명시하는 순서는 IFCN의 resting-state EEG 연구 권고와도 일치합니다. 이 프로젝트는 임상 EEG 표준을 충족하는 진단 시스템을 만드는 작업이 아닙니다.

  1. 계측 체인: 단위·극성·채널 순서·샘플링·시간축·저장을 검증합니다. 숙련된 랩은 사람을 완전히 분리한 벤치 상태에서 절연된 교정 신호원/팬텀으로 이득·잡음·주파수 응답도 확인합니다. 임의의 오디오 출력이나 접지된 함수발생기를 신체 전극에 연결하지 않습니다.
  2. 접촉과 알려진 반응: 임피던스·움직임·EOG/EMG를 확인하고, 후두부 눈 뜸/감음 같은 단순한 생리 대조를 기록합니다.
  3. 자극 체인: 자극 화면의 실제 타이밍과 이벤트 기록을 별도로 검증합니다. 새 디스플레이/OS/드라이버로 바꾸면 다시 확인합니다.
  4. 쉬운 task: 단일 자극과 OFF/ON으로 목표 반응의 존재·반복성부터 확인합니다.
  5. 분류와 재현성: 훈련·보정·평가를 구분하고 실패/제외 기준, 무반응, 오탐, 독립 재검사를 보고합니다. EEG가 실제로 있는지 확인하기 전에 복잡한 분류기를 추가하지 않습니다.

직접 참고한 자료와 적용 범위

앱 상단의 ‘공개 EEG 참고 예제’에서는 PhysioNet의 실제 눈 뜸/감음 기록과 Nakanishi 연구진의 SSVEP 자료를 볼 수 있습니다. 사용자의 EEG와는 별도이며, 참가자나 장비가 다르므로 진폭·정확도를 그대로 기대하지 않습니다. 실제 SSVEP에서도 매 시행의 FFT가 크게 튀지는 않는다는 점과, 보류를 제외하면 정확도가 달라지는 점을 함께 표시했습니다.
